# Документация SLogger

- Проверять сведения по коду: методы, пути, команды, конфигурацию, поля и статусы.
  Документ описывает действующее поведение и читается без истории чата.
- Пользовательские README — `README.md` и `README.ru.md`, обновляются вместе.
  Архитектура и инструкции агентам — `.ai/README.md` и `.ai/rules.md`.
  Планы изменений и требования — `openspec/changes/` и `openspec/specs/`.
- Перед изменением найти существующий документ по теме; не создавать параллельное
  описание того же механизма. Не заводить каталоги и оглавления ради шаблона.
- Писать коротко, без пересказа очевидного кода. Объяснять ограничения и причины
  неочевидного поведения. Примеры должны соответствовать SLogger.
- Ссылки между документами относительные. Ссылки на код — путь и имя метода,
  без номеров строк. Проверять существование целевых файлов.
- Для схем использовать Mermaid: без `<br/>`, вызывающий узел первым,
  запрос и ответ одним двунаправленным ребром. Названия методов сверять с кодом.
- После изменения поведения сверить связанные документы, конфигурацию, схемы API
  и тексты landing. Обновлять их по фактическому изменению контракта.
- Перед коммитом сообщить, какие документы проверены и что исправлено.
