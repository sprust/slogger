# Админский frontend SLogger

Правила работы с существующим frontend в `frontend/src/`.

- Сначала изучить соседнюю страницу и store. Использовать Vue 3, TypeScript,
  Element Plus и его иконки; существующие обёртки API, ошибок и UTC-времени.
  Не вводить новый layout/store framework ради переноса гайда.
- Типы API — `frontend/src/api-schema/admin-api-schema.ts`, только генератором.
  Не дублировать сгенерированные DTO вручную и не использовать `any` для обхода контракта.
- Страницы — `frontend/src/components/pages`, state и API — в соответствующем store.
  Компонент отвечает за отображение, store — за запросы и состояние.
- Табличные данные через `el-table`; сложная ячейка через scoped slot. Адаптивные
  карточки, detail, формы и диалоги используют существующие компоненты приложения.
  Общий компонент создаётся при реальном повторении, после проверки существующих компонентов.
- Loading/error/empty состояния явные. Ошибка запроса не оставляет loading навсегда.
  Не допускать перезаписи свежего результата устаревшим запросом.
- Фильтры/пагинация в URL следуют существующей странице: восстановить состояние
  при навигации, не записывать пустые значения, сброс фильтра сбрасывает страницу.
- Свойства компонентов типизированы, чтение props не мутирует объект родителя.
  Enum переводится в отдельном файле каждого enum, raw-значение не показывается.
- Layout не прыгает при загрузке, смене вкладок, фильтров, статусов. Резервировать
  место для временных блоков; кнопки/иконки остаются на месте, меняется disabled/loading.
  Подсказка одной вкладки живёт внутри неё.
- Использовать тему и CSS-переменные приложения; не фиксировать цвета, ломая
  dark/light режимы. Семантические цвета статусов, читаемые подписи, единицы,
  легенды и пустое состояние для графиков. Не добавлять декоративную анимацию,
  мешающую чтению; учитывать reduced motion.
- Формы сохраняют размеры при валидации и загрузке, ошибки привязаны к полям;
  удаление и доступ к действиям соответствуют backend и middleware маршрутов.
- После правок — `make frontend-npm-build`; HTTP-контракт сначала регенерируется
  `make oa-generate`. Проверить связанные landing/demo, если меняется продуктовый сценарий.
