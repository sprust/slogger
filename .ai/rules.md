# Правила кода SLogger

Перенесены из PMS. Применяются к создаваемому и затронутому коду вместе с
[README.md](README.md). Источник и границы переноса — [pms-import.md](pms-import.md).
Правила предметной области PMS не вводят в SLogger отели, клиентские роли,
ActionResolver, запрет удаления или другие отсутствующие механизмы.

## Перед изменениями

- Читать `.ai/README.md`, этот файл и тематические гайды из `.ai/skills/` целиком.
  Читать существующую документацию изменяемого модуля, если она есть.
- Истина о текущем поведении — код; инструкции задают требования к изменениям.
  Расхождения документации с кодом исправлять или явно отмечать.
- Найти аналогичный сценарий. Переиспользовать подходящие Actions, проверки,
  DTO и обработчики. Не добавлять несогласованный рефакторинг соседних механизмов.
- Применять правила ко всему затронутому файлу, в том числе к соседним замыканиям.
  Не менять внешний контракт ради оформления.
- Команды Claude и навыки Codex обновлять согласованно. Одна операция — один
  навык для каждого агента; OpenSpec использует существующие `openspec-*`.

## Оформление кода

Полный текст правил и примеров PMS скопирован без пересказа в
[code-style.md](code-style.md). Читать его перед любым изменением PHP-кода.
Не заменять исходные правила локальными упрощениями.

Прямые указания пользователя сохраняются: foreach и preg_match не разрывать,
миграции не переформатировать; короткие простые вызовы и массивы не раскрывать
механически; результат UseCase в Resource переносить на отдельную строку.

## Типы и контракты

- У Object/Parameters нет defaults даже для nullable. Исключения: поисковые
  `Find*Parameters` и тестовые фабрики, описанные в соответствующих гайдах.

- Доверять объявленному типу. Не делать ненулевое поле nullable и не добавлять
  защитные ветки, скрывающие нарушение данных. Реально допустимое отсутствие
  (включая удалённый объект) выражать nullable и обрабатывать явно.
- Публичные входы и результаты типизированы: примитивы, enum, Parameters, DTO,
  typed arrays с PHPDoc. Не вводить непрозрачные ассоциативные карты для
  доменного результата: возвращать список DTO с явным полем ключа.
- Raw `array<int|string, mixed>` допустим на границе БД, HTTP, внешнего API,
  сериализации/десериализации. Сразу преобразовывать в типизированные данные.
- Публичные Domain-методы не принимают Entity/Object: входные составные данные
  оформляются собственными Parameters. Исключение только для преобразователей
  модульного `Transports/*Transport`, по образцу PMS. `Domain/Services/Mappers`
  не создавать. Чтение и оркестрация остаются Domain; Transports преобразуют
  типизированные данные по разрешённому направлению.
- Entities/Parameters — readonly; DTO не содержит бизнес-поведение.
  Входы Actions/UseCases используют Parameters своего модуля. Межмодульные
  зависимости, включая вложенные DTO, определяет матрица README.
- Enum-подобные поля имеют собственный enum, а не строку. Если есть Rules-класс
  для enum, использовать его. Открытые значения внешнего протокола не
  превращать в закрытый enum без изменения согласованного контракта.
- В модулях не использовать `@phpstan-type` / `@phpstan-import-type`: inline
  shape или DTO. Эти aliases допустимы в пакетах и отрицательных fixtures анализатора.
- Не использовать `Stringable` как скрытое преобразование. Нужное преобразование
  выполнять явно. Никаких `method_exists`, `property_exists`, проверки callable
  или Reflection ради duck typing: объявлять интерфейс и использовать `instanceof`.
  Статический анализ исходного кода использует API рефлексии анализатора по назначению.
- Пустой массив: `count($items) === 0`, не `$items === []`. Вместо `isset`/`empty`
  выбирать точное условие: `array_key_exists`, `=== null`, `=== ''`, `count`.
- Группировать скобками смешанные `&&`/`||` и условия тернарных выражений.

## Классы, DI и замыкания

- Оформление классов, порядок зависимостей и замыкания — по [code-style.md](code-style.md).
  Обычный DI, без ActionResolver и proxy.
- Для SDK пакет объявляет конфигурационный интерфейс без зависимости от Laravel.
  Значения приложения и binding находятся в provider модуля-потребителя.
- Singleton в SConcur не хранит состояние запроса, пользователя или текущего job.

## Хранилище и миграции

- Миграции сохраняют принятый стиль Laravel; массовое форматирование и проверка
  длины строк пропускают `database/migrations`.

- Репозитории возвращают примитивы/DTO, не Model/Builder; не вызывают другой
  репозиторий. Оркестрация нескольких хранилищ находится в Domain.
- Для Eloquent не использовать `$fillable`, `Model::create`, `updateOrCreate`
  и `$model->update`: явные присваивания и `saveOrFail`. Точечный query-builder
  update одного-двух полей допускается. SConcur MongoDB/ClickHouse сохраняют
  свои операции; массовые изменения не заменять построчной загрузкой.
- Новые собственные MongoDB-поля и ключи документов — camelCase. Внешние
  payload/log/trace сохраняют исходный контракт, произвольно ключи не переименовывать.
- Физическое удаление сохраняется. `withTrashed` допускается там, где история
  ссылается на удалённую сущность; не менять это поведение на PMS status-policy.
- Добавляя обязательное поле MongoDB, проставить его старым документам в том же
  релизе. Большие выборки/миграции — чанками с курсором по `_id`, без пересканирования
  начала. Различать отсутствующее поле и настоящий null в фильтре.
- Миграция использует query builder и сырые значения, не текущие модели/enum.
  Значение enum можно пояснить комментарием. Timestamp имени файла — UTC.
- Новые колонки: id, бизнес-поля, status, timestamps. Ссылочные колонки индексировать;
  отдельный индекс не удалять только потому, что колонка первая в составном.
  Существующую схему и FK не менять в рамках архитектурного рефакторинга.
- Новый репозиторий/обновление: [skills/repositories.md](skills/repositories.md).

## Исключения, события, очереди

- Каждый модуль с доменными ошибками содержит `Domain/Exceptions/Abstract<Module>Exception`,
  наследующий `Exception`, как в PMS. Конкретные ошибки наследуют базовый класс своего
  модуля; менеджер проверяет его через `instanceof`. `getDontReport` перечисляет только
  конкретные ожидаемые ошибки. Новый наследник автоматически обрабатывается и репортится;
  fallback-сообщение не раскрывает внутренний контекст. Протокольные ошибки — Infrastructure.
- Ошибки предметной области — конкретные Domain Exceptions с readonly контекстом
  и английским dev-сообщением. HTTP mapping — модульный ExceptionManager,
  сообщения и статусы сохраняют текущий API.
- Checked-style доменные исключения (не RuntimeException) указывать в `@throws`
  на всей цепочке реализации. Не ставить `@throws Throwable`, RuntimeException
  и `@throws` в интерфейсах. Не менять контракт исключений существующего API
  на union-результат только ради этого правила.
- В catch имя `$exception`; если не используется — без переменной.
  Ловить конкретный ожидаемый тип. Общий Throwable оставлять на действительных
  границах инфраструктуры/репортинга, где нужно обработать любую ошибку.
- Не скрывать гонку перехватом ошибки уникальности: mutex с повторной проверкой
  внутри; уникальный индекс сохраняется как инвариант.
- Application jobs, events и report идут через DispatcherInterface; регистрацию
  выполняют модульные providers. Отказ маршрута логируется прямо, без рекурсивного report.
- Запланированная тяжёлая работа — в job с общим бизнес-сценарием для ручной команды.
  Два существующих scheduled jobs проходят dispatcher; SConcur tasks и действующие
  scheduled commands сохраняют согласованное расписание.

## HTTP, конфигурация и чувствительные данные

- Контроллер бизнес-эндпоинта вызывает один локальный UseCase; тот возвращает
  полный DTO ответа. Admin UseCase имеет суффикс `ByAdminUseCase`, системный — без
  пользовательского суффикса. Протокольный разбор MCP остаётся Infrastructure.
- Resource принимает один DTO, без дополнительных флагов/коллекций вторым аргументом.
- Правила FormRequest вертикально. Не применять `withValidator`, если достаточно
  обычных правил; не прятать проверки ради обхода генератора.
- `$request->validated()` сохранять в `$validated`, значения получать через
  существующий `Common\Helpers\ArrayValueGetter`. Не приводить raw-поля вручную.
- Для переводов DI `Illuminate\Contracts\Translation\Translator`, не `__`/`trans`.
  В сериализуемом job зависимость разрешается в обработчике, не в payload.
- Ключи config/translation/route/view писать литералом по месту. Не скрывать их
  за helper ради склейки строки. Исключение — инфраструктура, действительно
  работающая с произвольными ключами (например, маршрутизация очередей).
- Пароли, токены, private keys во входе Domain — Parameters с JsonSerializable;
  чувствительные поля сериализуются как `|hidden|` либо null. Большие неограниченные
  payload/деревья также скрывать при диагностической сериализации, оставляя идентификаторы.
- Новые env-переменные добавлять в соответствующий `.env.example` с тем же default,
  тематическим блоком и порядком. В SLogger нет контекстов pms/pms-bmr.
- Генерируемые схемы/TS менять генератором, исправляя источник. Проверять diff
  после генерации и не присваивать чужие изменения.

## Тесты, UI, документация и git

- Применять [tests](skills/tests.md), [admin](skills/admin.md),
  [documentation](skills/documentation.md) по теме задачи.
- Использовать существующие UI-компоненты и Element Plus; сохранять размеры и
  расположение элементов при загрузке и смене состояния. Переводы enum — отдельными
  файлами. Не выводить raw enum пользователю.
- Git: английский, одна короткая строка до 120 символов; `module: description`
  только для настоящего бизнес-модуля, иначе без псевдо-префикса. Единственный
  трейлер AI-коммита — `Co-Authored-By`. Ветки feature/refactor/hotfix только по
  указанию пользователя. Не переписывать историю без отдельного разрешения.
- Коммит и push требуют своих разрешений по README. Перед коммитом сверить
  документацию, назвать проверенные документы вместе с сообщением коммита.
- Перед push — `make check`; HTTP/contract enum — `make oa-generate`;
  изменённый frontend/generated TypeScript — `make frontend-npm-build`.
- В ответах ссылки на код — полный путь от корня и строка конкретной логики;
  в документах ссылки на файлы без хрупких номеров строк.
