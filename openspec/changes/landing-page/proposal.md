# Proposal

## Why

У SLogger нет страницы, которая коротко объясняет, что делает система и как она устроена. README подробный, но рассчитан на того, кто разворачивает установку. Людям без доступа к панели показать нечего. Нужна публичная страница-презентация на `/landing`, которая показывает работу системы теми же компонентами, что и админка, на демо-данных.

## What Changes

- Новый публичный маршрут фронтенда `/landing`: открывается без входа и не делает запросов к API.
- На публичных маршрутах нет шапки и прокрутки панели: страница стоит по центру с отступами по бокам и прокручивается обычным скроллом. У страницы своя верхняя строка с названием и ссылкой на вход в панель.
- Страница на русском, в сухом тоне, из разделов:
  1. Что это: назначение системы.
  2. Путь данных: клиент → TCP-приёмник → буфер → слияние → ClickHouse, схема на vue-flow.
  3. Поиск трейсов: список трейсов с рабочей панелью фильтров на демо-данных, данные трейса, примеры поиска по ненормализованным `data` (вложенные поля, массивы значений и объектов, null, наличие поля).
  4. Трейс и дерево вызовов: демо-дерево на `TraceTreeRowView` с показателями трейсов, сквозное дерево нескольких сервисов. Профилирование не показывается.
  5. Графики: количество, длительность, память и CPU с перцентилями на `TraceTimelineChart`.
  6. Метрики приёма: сколько трейсов сервис прислал, принял в буфер и записал, на `TraceMetricsChart`.
  7. Смотрители и уведомления: правило → инцидент → события на `IncidentEventsTable` → каналы Telegram, Slack, JSON.
  8. MCP: что это, сценарии вопросов с цепочками инструментов, команда подключения.
  9. Устройство и хранилища: рантайм SConcur, роли ClickHouse, MongoDB, MySQL, RabbitMQ, Redis, автоочистка.
- Все данные на странице — статические демо-данные из кода фронтенда, без обращения к установке.
- Тексты лежат отдельно от разметки, чтобы позже добавить английскую версию.

## Capabilities

### New Capabilities

- `landing-page`: публичная страница-презентация на `/landing`: доступ без входа, отсутствие запросов к API, состав разделов, сценарии MCP, демо-данные, стабильная раскладка.

### Modified Capabilities

Нет.

## Impact

- Фронтенд:
  - `frontend/src/utils/router.ts` — маршрут `/landing` с признаком публичности, пропуск проверки входа для публичных маршрутов;
  - `frontend/src/App.vue` — на публичных маршрутах своя раскладка без шапки и `el-scrollbar`;
  - новая папка `frontend/src/components/pages/landing` — страница, разделы, демо-данные, тексты.
- Перевод на props ещё четырёх частей агрегатора без изменения поведения: таблицы трейсов (`TraceTracesTableView`), просмотра данных трейса (`TraceAggregatorTraceDataNode`), строк условий по полям данных (`TraceAggregatorTracesCustomFields`) панели выбранных типов, тегов и статусов (`FilterTagsBarView`), панели данных выбранного трейса в дереве (`TraceDetailView`) и таблицы смотрителей (`WatcherListView`). Логика условий по полям данных выносится из store в отдельный модуль.
- Зависит от change `landing-reusable-components`: использует `TraceTreeRowView`, слот `#row` виртуального списка, `TraceTimelineChart`, `TraceMetricsChart`, `IncidentEventsTable`, `incidentEventColumns.ts`. Без изменений использует `TraceItemMetrics`, `TraceId` и JSON-вьюер.
- `app/Modules` и слои Deptrac не затрагиваются, бэкенд, API и OpenAPI не меняются. Публичный маршрут отдаёт тот же `index.html`, что и остальные маршруты SPA.
- Новых зависимостей нет: `vue-flow`, `chart.js` и Element Plus уже есть.
