# Design

## Context

Мотивация — в `proposal.md`, требования — в `specs/landing-page/spec.md`. Сейчас приложение устроено так:

- `frontend/src/utils/router.ts`: `beforeEach` на каждом переходе вызывает `authStore.auth()`, если пользователя ещё нет. При сохранённом токене это запрос `authMeList`, а при успехе подключается WebSocket-пул (`EchoContainer.connect()` в `authStore`). Без пользователя всё, кроме `/login`, уходит на `/login`. Маршрут без имени уходит на дашборд.
- `frontend/src/App.vue`: `el-header` с `Header` при наличии пользователя, ниже `el-scrollbar` с `router-view`. На `<html>` стоит класс `dark` — тёмная тема Element.
- Фронтенд — SPA на Vite. Dev-сервер и `vite preview` отдают `index.html` на любой путь, поэтому `/landing` открывается по прямой ссылке без правок сервера.
- После change `landing-reusable-components` компоненты отображения дерева трейса, графиков, метрик и событий инцидента работают на props без store. Профилирование лендинг не показывает: его будут удалять.

## Goals / Non-Goals

**Goals:**
- Публичный маршрут без запросов к установке.
- Страница из восьми разделов на демо-данных, собранная из компонентов панели.
- Тексты отделены от разметки, чтобы позже добавить английский.

**Non-Goals:**
- Английская версия и переключатель языка.
- Адаптивная вёрстка под телефон. Страница рассчитана на ширину от 1280px, на более узком экране широкие демо-блоки прокручиваются по горизонтали внутри себя.
- SEO, серверный рендеринг, отдельные мета-теги.
- Ссылка на лендинг со страниц панели.
- Изменения бэкенда, API и MCP-сервера.

## Decisions

### 1. Публичность через `meta.public`

У маршрута `/landing` (`routes.landing`) стоит `meta: {public: true}`. В начале `beforeEach` стоит проверка: если `to.meta.public`, сразу вызывается `next()`, без `authStore.auth()` и без перенаправлений. Так гость не делает запроса `authMeList`, и WebSocket-пул не подключается. Авторизованный пользователь тоже видит страницу и не уходит на дашборд.

Отвергнутый вариант — особый случай по имени маршрута рядом с `login`. Признак в `meta` не требует правок guard'а для следующего публичного маршрута.

### 2. Своя раскладка на публичных маршрутах

`App.vue` не рисует `el-header`, если `$route.meta.public`. Пустой `el-header` всё равно занимает 60px, поэтому скрывается весь заголовок, а не только `Header`. `el-scrollbar` остаётся, и прокрутка страницы такая же, как в панели.

Верхняя строка лендинга — часть самой страницы: название SLogger, краткая подпись, якорные ссылки на разделы и `router-link` на `/login` с подписью «Войти в панель».

### 3. Структура папки

```
frontend/src/components/pages/landing/
  Landing.vue                  - top bar and the section order
  sections/
    LandingAbout.vue           - 1. what it is
    LandingDataPath.vue        - 2. data path (vue-flow)
    LandingTraceTree.vue       - 3. trace tree
    LandingSearch.vue          - 4. search and charts
    LandingMetrics.vue         - 5. intake metrics
    LandingWatchers.vue        - 6. watchers and notifications
    LandingMcp.vue             - 7. MCP
    LandingStack.vue           - 8. runtime and storage
  content/
    ru.ts                      - texts of all sections
    mcpScenarios.ru.ts         - MCP scenarios: question, steps, answer
  demo/
    demoTraceTree.ts           - tree nodes
    demoTimeline.ts            - aggregator graph data and options
    demoMetrics.ts             - slots and rows of the intake metrics
    demoIncident.ts            - incident events and columns
```

`Landing.vue` подключается в роутер лениво, как остальные страницы, поэтому код лендинга не попадает в бандл панели и наоборот.

### 4. Тексты — объекты в `content/ru.ts`

Каждый раздел получает типизированный объект текстов (`LandingAboutText`, `LandingDataPathText` и так далее): заголовок, абзацы, подписи демо-блоков. Это объекты, а не массивы с ключами-смыслами. Разметка импортирует `ru.ts` напрямую. Английская версия позже станет `en.ts` того же типа и переключателем выбора. Пока выбирать не из чего, поэтому переключателя нет.

Тексты пишутся по README и коду, каждое утверждение сверяется с источником (раздел «Documentation Style» в `.ai/README.md`). Жирный только для одного-двух ключевых терминов, без рекламных оборотов.

### 5. Демо-данные — детерминированные модули

Демо-данные — константы и функции без случайности: одни и те же числа при каждой загрузке, никакого `Math.random()` и `Date.now()`. Время зафиксировано вокруг одной даты, поэтому подписи осей и времени стабильны. Типы берутся из типов панели (`TraceTreeNode`, `DashboardTraceMetric`, `WatcherIncidentEvent`), импортированных как `import type`. Так демо-данные проверяются тем же `vue-tsc`, что и панель.

Сюжет данных сквозной, чтобы разделы ссылались друг на друга: сервисы `gateway`, `billing`, `crm`. Запрос `POST /api/invoices` в `gateway` вызывает `billing`, а тот выполняет SQL-запросы и задачу очереди. Метрики показывают всплеск в 14:20–14:40, смотритель медленных трейсов заводит по нему инцидент, MCP-сценарий «кто даёт нагрузку» разбирает тот же всплеск.

### 6. Демо-дерево: локальное состояние

`LandingTraceTree` держит иерархию узлов и множество свёрнутых id в своём `data`. Видимые строки он разворачивает в плоский список `TraceTreeNode` с `depth` так же, как это делает store дерева, и передаёт список в `TraceAggregatorTraceTreeVirtual`. В слот `#row` идёт `TraceTreeRowView`. События `toggle-collapse` и `select` меняют локальное состояние: выбранная строка подсвечивается, под деревом показываются её данные в `JsonViewer`. `find-tree`, `show-json`, `indicate` и `load-more` на лендинге не обрабатываются. Узлы получают `childrenCount`, только если дети уже лежат в демо-данных, поэтому кнопки «more» не появляется.

Блок дерева фиксированной высоты (например, 360px), блок данных узла тоже. Раскрытие и выбор не меняют размеров (требование «Стабильная раскладка»).

### 7. Схема пути данных

`LandingDataPath` рисует `VueFlow` со статичными узлами и рёбрами без перетаскивания и масштабирования колёсиком: клиент → сокет приёмника → буфер MongoDB → транспортёр (слияние с `pendingTraces`) → ClickHouse `traces` → панель и MCP. Подписи рёбер — настоящие имена шагов из README («Поток данных»). Узлы — `el-card` с одной строкой текста. Под схемой — короткие абзацы про слияние половин трейса и надёжность буфера.

### 8. Графики и метрики

`LandingSearch`: `TraceTimelineChart` с демо-`data` и `options` по формату store графиков агрегатора. Над графиком — статичная строка фильтров из `el-tag` (сервис, тип, `data.response.status >= 500`), показывающая, чем можно сузить график. Это иллюстрация, без интерактивного фильтра.

`LandingMetrics`: `TraceMetricsChart` с демо-слотами и строками, без `clickHint`. Над ним — та же шапка, что в панели, только итоги из `traceMetricsValues.ts`, без выбора типов и Refresh.

Высоты графиков фиксированные.

### 9. Смотрители

`LandingWatchers`: карточка правила (тип «медленные трейсы», порог, окно, фильтр по сервису) из `el-descriptions`. Под ней — `IncidentEventsTable` с демо-событиями и колонками из `incidentEventColumns.ts`, `canOpenInAggregator = false`, `exhausted = true`. Справа — список каналов (Telegram, Slack, JSON) с иконкой и одной строкой описания. Раскрытие строки таблицы меняет её высоту, поэтому таблица лежит в блоке фиксированной высоты с внутренней прокруткой.

### 10. MCP

`LandingMcp`: абзац о назначении, затем `el-tabs` по сценариям из `mcpScenarios.ru.ts`. Сценарий — объект: `title`, `question`, `steps` (инструмент, параметры, итог шага) и `answer`. Шаги показывает `el-timeline`. Панель вкладок фиксированной высоты с внутренней прокруткой, поэтому переключение не сдвигает страницу. Ниже — статичный блок с командой `claude mcp add --transport http --scope user slogger-<имя> https://<адрес>/mcp --header "Authorization: Bearer <token>"` и пояснением, что токен выдаёт страница MCP панели.

Имена инструментов и параметров сверены с `app/Modules/Mcp/Infrastructure/Tools`: у `aggregate_traces` группировка задаётся параметром `by` (`service`, `type`, `status`, `hour`, `minute10`), у `search_traces` есть `duration_from`, `data_filter`, `data_fields`, у `compare_trace_groups` — `group_a_statuses`, `group_b_statuses`, `by` (`type`, `service`, `tag`, `data.<key>`). У `search_trace_tree` есть фильтры `service_ids`, `types`, `tags`, `statuses`, фильтра по длительности нет, поэтому сценарии не обещают с его помощью найти медленные вызовы. В сценарии «кто даёт нагрузку» источник определяется по выборке трейсов через `data_fields` и по родителю в дереве, без обещания точного подсчёта.

### 11. Без шрифтов и сдвигов

По правилам фронтенда размер шрифта не задаётся. Заголовки разделов — `h2` и `h3` со стилями браузера и Element, текст — `el-text`. Место под всё, что появляется и исчезает, резервируется заранее.

## Risks / Trade-offs

- [Компоненты панели подписаны по-английски (Refresh, tree, json, Occurred at), а лендинг на русском] → Подписи внутри демо-блоков остаются как в панели: блок показывает, как выглядит панель. Русскими остаются только тексты разделов.
- [Тексты расходятся с системой по мере её развития] → Тексты собраны в `content/ru.ts`. В задачах есть сверка с README и кодом. Сценарии MCP проверяются по `tools/list`.
- [`vue-flow` в двух разделах увеличивает чанк лендинга] → Чанк загружается лениво только на `/landing`. Панель его не грузит.
- [Демо-формат графиков разойдётся с форматом store после будущих правок] → Демо-данные типизированы типами панели, поэтому `vue-tsc` поймает расхождение при сборке.
- [Пользователь панели откроет `/landing`, и шапка исчезнет] → Это ожидаемо: у страницы своя верхняя строка, а возврат в панель — ссылкой из неё или кнопкой браузера назад.
