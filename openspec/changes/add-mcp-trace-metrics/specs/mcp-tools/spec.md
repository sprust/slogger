## ADDED Requirements

### Requirement: get_trace_metrics

Инструмент `get_trace_metrics` SHALL возвращать ряд метрик трейсов за период тем же расчётом, что график на странице трейсов в UI, и SHALL строить для этого тот же динамический индекс, что построил бы UI при тех же фильтрах, шаге и периоде.

Аргументы:
- `period` — обязательный, один из пресетов UI не длиннее суток: `5 minutes`, `30 minutes`, `1 hour`, `4 hours`, `12 hours`, `1 day`; другой пресет SHALL давать ошибку JSON-RPC `-32602`;
- `to` — необязательный конец периода в ISO 8601, по умолчанию текущий момент;
- `step` — необязательный шаг из тех, что UI предлагает для пресета; без него SHALL браться шаг по умолчанию: `5 minutes` — `s5`, `30 minutes` — `s30`, `1 hour` — `min`, `4 hours` — `min5`, `12 hours` — `min30`, `1 day` — `min30`;
- `metrics` — необязательный список из `count`, `duration`, `memory`, `cpu`, по умолчанию `count` и `duration`;
- фильтры, все необязательные: `service_ids`, `types`, `tags`, `statuses` (каждый до 20 значений), `duration_from`, `duration_to`, `memory_from`, `memory_to`, `cpu_from`, `cpu_to` (числа в тех же единицах, что в `get_trace`).

Шаг не из списка пресета SHALL давать ошибку инструмента `step_not_allowed` со списком допустимых шагов. Время `to` не в ISO 8601 SHALL давать ошибку инструмента `invalid_time`. Неизвестный id сервиса SHALL давать ошибку инструмента `service_not_found` со списком неизвестных id.

Готовый ответ SHALL содержать `status: "ready"`, `period`, `step`, `from` (начало первого шага), `to`, `metrics` и `points` — все шаги периода по возрастанию времени, включая шаги без трейсов. На шаг: `from`, `to` (последний момент шага) и по ключу на каждую запрошенную метрику: `count` — число трейсов, остальные — объект с `avg`, `min`, `max`, `p50`, `p95`, `p99`. В шаге без трейсов `count` SHALL быть `0`.

Пока индекс строится, ответ SHALL быть не ошибкой, а статусом `{"status": "index_building", "index_id": ..., "retry_after_seconds": 10, "hint": ...}`, где `hint` просит повторить тот же вызов позже и предупреждает, что другой набор фильтров, шаг или период начнут строить другой индекс. Если построение индекса завершилось ошибкой, ответ SHALL быть ошибкой инструмента `index_error` с текстом ошибки индекса.

Описание инструмента SHALL говорить, что инструмент строит индекс в фоне, что смена значений фильтров при том же наборе фильтров, шаге и часах периода переиспользует индекс, а новый набор фильтров, шаг или час строят новый.

#### Scenario: Упавшие трейсы за час
- **WHEN** индекс готов, и модель вызывает `get_trace_metrics` с `period: "1 hour"`, `service_ids: [2]`, `statuses: ["failed"]`
- **THEN** ответ содержит `status: "ready"`, `step: "min"`, `points` по минутам с `count` и `duration` в каждом шаге

#### Scenario: Пустые шаги
- **WHEN** трейсы были только в двух минутах часа, и модель вызывает `get_trace_metrics` с `period: "1 hour"`
- **THEN** `points` содержит все минуты периода, в минутах без трейсов `count` равно `0`

#### Scenario: Выбранные метрики
- **WHEN** модель вызывает `get_trace_metrics` с `metrics: ["cpu"]`
- **THEN** в шагах есть ключ `cpu` с `avg`, `min`, `max`, `p50`, `p95`, `p99` и нет ключей `count` и `duration`

#### Scenario: Индекс строится
- **WHEN** индекса для набора фильтров и часов ещё нет, и модель вызывает `get_trace_metrics`
- **THEN** построение запускается, ответ — статус `index_building` с `index_id` без `isError`

#### Scenario: Смена значений фильтра
- **WHEN** модель получила ответ `ready` с `types: ["request"]` и в том же часе вызывает `get_trace_metrics` с тем же `period`, шагом и `types: ["job"]`
- **THEN** ответ — `ready` без построения нового индекса

#### Scenario: Индекс упал
- **WHEN** построение индекса завершилось ошибкой, и модель вызывает `get_trace_metrics` с теми же аргументами
- **THEN** ответ — ошибка инструмента `index_error` с текстом ошибки индекса

#### Scenario: Недопустимый шаг
- **WHEN** модель вызывает `get_trace_metrics` с `period: "1 day"` и `step: "s5"`
- **THEN** ответ — ошибка инструмента `step_not_allowed`, в тексте которой перечислены `min30`, `h`, `h4`, `h12`

#### Scenario: Слишком длинный пресет
- **WHEN** модель вызывает `get_trace_metrics` с `period: "7 days"`
- **THEN** ответ содержит ошибку JSON-RPC `-32602`, в тексте которой названо поле `period`

#### Scenario: Неизвестный сервис
- **WHEN** модель вызывает `get_trace_metrics` с `service_ids: [999]`, а такого сервиса нет
- **THEN** ответ — ошибка инструмента `service_not_found`, в тексте которой есть `999`

#### Scenario: Неверное время
- **WHEN** модель вызывает `get_trace_metrics` с `to: "yesterday"`
- **THEN** ответ — ошибка инструмента `invalid_time`, в тексте которой названо `to`
