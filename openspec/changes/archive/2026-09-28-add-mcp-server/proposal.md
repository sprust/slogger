## Why

Расследование по трейсам сейчас ведётся только руками в UI. LLM-клиенты (Claude Code и другие) умеют сами вести такое расследование по вопросу в свободной форме — «почему у сервиса 1 иногда падают API-запросы», — если сервер отдаёт им данные по протоколу MCP. Модель, цикл агента и оплата токенов остаются на стороне клиента, SLogger даёт только инструменты и инструкции.

Это первое изменение из серии. Оно даёт рабочий MCP-сервер с подключениями и инструментами, которым не нужны динамические индексы трейсов. Запросы по трейсам с индексами, составные инструменты и ссылки на UI идут следующими изменениями: `add-mcp-trace-queries`, `add-mcp-trace-groups`, `add-mcp-trace-links`.

## What Changes

- Новый модуль `app/Modules/Mcp`: подключения MCP, сервер протокола, инструменты и мосты в другие модули.
- Эндпоинт `POST /mcp` по протоколу MCP ревизии `2026-07-28`, транспорт Streamable HTTP, только ответы `application/json`, без сессий и без SSE. Методы: `server/discover`, `tools/list`, `tools/call`, `prompts/list`, `prompts/get` (список промптов в этом изменении пуст). Другие ревизии, в том числе рукопожатие `initialize`, не поддерживаются.
- Подключения MCP — таблица `mcps` со статическим токеном, без привязки к пользователю. Подключение можно выключить и удалить из ЛК. Admin API `/mcps`: список, создание, изменение, выключение, перевыпуск токена, удаление.
- Страница `/mcps` на фронте: подключения, токен, готовая команда `claude mcp add` и вариант для `.mcp.json`.
- Имя инсталляции `server_name` (`MCP_SERVER_NAME`, по умолчанию `APP_ENV`): попадает в имя сервера, в инструкции, в каждый ответ инструмента и в шапку UI.
- Инструменты, которым не нужен динамический индекс: `list_services`, `get_data_range`, `list_incidents`, `get_incident_events`, `get_trace`, `get_trace_data`, `get_trace_tree` (со статусом `tree_building`), `find_in_trace_tree`. Профилирование трейсов MCP не отдаёт.
- Все инструменты только читают.
- Раздел «MCP» в `README.md` и `README.ru.md`: как подключить клиента.
- Удалён `.ai/plans/mcp-server.md`: план заменяется этой серией изменений. Черновики следующих фаз (защита от дорогих запросов, промпты, составные инструменты, текст README) остаются в истории git, коммит `b6e51180`.

## Capabilities

### New Capabilities

- `mcp-protocol`: эндпоинт MCP — транспорт, проверка заголовков и версии, методы протокола, коды ошибок, инструкции сервера, имя инсталляции.
- `mcp-connections`: подключения MCP — токены, включение и выключение, `last_used_at`, admin API и страница `/mcps`.
- `mcp-tools`: инструменты MCP без динамических индексов — аргументы, ответы, ошибки инструментов, статус построения дерева трейса.

### Modified Capabilities

Нет.

## Impact

- Модули и слои Deptrac:
  - `Mcp` (новый) — `Domain`, `Entities`, `Parameters`, `Repositories`, `Infrastructure`;
  - `Service`, `Watcher`, `Trace` — не меняются; `Mcp\Domain` вызывает их `Domain\Actions` в одну сторону, эти рёбра вписываются в `.ai/README.md` → Cross-Module Dependencies;
  - `Models` — новая модель `App\Models\Mcps\Mcp`.
- БД: миграция MySQL `mcps`.
- HTTP: новый маршрут `/mcp` вне admin API; новые маршруты admin API `/mcps` — нужен `make oa-generate`.
- Фронтенд: страница `/mcps`, пункт меню, имя инсталляции в шапке — нужен `make frontend-npm-build`.
- Конфигурация: `config/mcp.php`, переменная `MCP_SERVER_NAME` и лимиты ответов, `.env.example`.
- Документация: `README.md`, `README.ru.md`, `.ai/README.md`.
- Новых зависимостей нет: протокол реализуется своим кодом, без `laravel/mcp` и сторонних SDK.
