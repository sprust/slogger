# mcp-connections Specification

## Purpose
Подключения MCP: именованные статические токены, по которым LLM-клиенты ходят на эндпоинт `/mcp`, и управление ими через admin API и страницу `/mcps`.

## Requirements

### Requirement: Подключение MCP

Подключение SHALL иметь `id`, `name`, `token`, `enabled`, `requests_count`, `last_used_at`, `created_at`, `updated_at`. Подключение не привязано к пользователю и даёт чтение всех данных инсталляции.

#### Scenario: Новое подключение
- **WHEN** пользователь создаёт подключение с именем «Claude Code — Вася»
- **THEN** у подключения есть токен, `enabled` равно `true`, `requests_count` равно `0`, `last_used_at` пусто

### Requirement: Токен подключения

При создании и перевыпуске система SHALL генерировать новый уникальный токен из 50 символов. Токен хранится открытым текстом и отдаётся в admin API в любой момент. После перевыпуска старый токен SHALL сразу перестать приниматься.

#### Scenario: Уникальный токен
- **WHEN** пользователь создаёт два подключения
- **THEN** у каждого токен длиной 50 символов, и токены различаются

#### Scenario: Перевыпуск токена
- **WHEN** пользователь перевыпускает токен подключения, а клиент продолжает слать старый токен на `/mcp`
- **THEN** система отвечает клиенту `401`, а запрос с новым токеном проходит аутентификацию

### Requirement: Выключенное и удалённое подключение

Токен выключенного (`enabled = false`) или удалённого подключения SHALL NOT приниматься эндпоинтом `/mcp`.

#### Scenario: Выключенное подключение
- **WHEN** подключение выключено, и клиент шлёт его токен на `/mcp`
- **THEN** система отвечает `401`

#### Scenario: Удалённое подключение
- **WHEN** подключение удалено, и клиент шлёт его токен на `/mcp`
- **THEN** система отвечает `401`

### Requirement: Счётчик запросов и время последнего использования

После каждого запроса к `/mcp`, прошедшего аутентификацию, система SHALL увеличить `requests_count` подключения на единицу и записать в `last_used_at` время запроса, одним атомарным обновлением. Запрос с неверным или выключенным токеном не считается.

#### Scenario: Первое использование
- **WHEN** клиент впервые делает запрос с токеном подключения
- **THEN** `requests_count` подключения равно `1`, `last_used_at` — время запроса

#### Scenario: Частые запросы
- **WHEN** клиент делает второй запрос через 10 секунд после первого
- **THEN** `requests_count` равно `2`, `last_used_at` — время второго запроса

#### Scenario: Неверный токен
- **WHEN** клиент шлёт на `/mcp` неизвестный токен
- **THEN** система отвечает `401`, ни у одного подключения `requests_count` не меняется

### Requirement: Admin API подключений

Система SHALL предоставлять в admin API под обычной сессией пользователя маршруты: `GET /mcps` (список), `POST /mcps` (создать, `name`: строка от 1 до 255 символов), `GET /mcps/{id}`, `PATCH /mcps/{id}` (изменить `name` и `enabled`), `PATCH /mcps/{id}/token` (перевыпустить токен), `DELETE /mcps/{id}`. Ресурс подключения SHALL содержать `id`, `name`, `token`, `enabled`, `requests_count`, `last_used_at`, `created_at`, `updated_at`. Маршрут `GET /mcps/settings` SHALL отдавать настройки инсталляции: `server_name` и `endpoint_url` эндпоинта `/mcp`. Без сессии SHALL возвращаться `401`, для несуществующего `id` — `404`.

#### Scenario: Без сессии
- **WHEN** запрос к `GET /mcps` идёт без токена сессии пользователя
- **THEN** система отвечает `401`

#### Scenario: Создание
- **WHEN** пользователь отправляет `POST /mcps` с `name` «CI-агент»
- **THEN** ответ содержит новое подключение с токеном

#### Scenario: Пустое имя
- **WHEN** пользователь отправляет `POST /mcps` с пустым `name`
- **THEN** система отвечает ошибкой валидации `422`

#### Scenario: Настройки инсталляции
- **WHEN** пользователь запрашивает `GET /mcps/settings` на инсталляции `stand` с `APP_URL=https://slogger.stand.example.com`
- **THEN** ответ содержит `server_name` `stand` и `endpoint_url` `https://slogger.stand.example.com/mcp`

#### Scenario: Выключение
- **WHEN** пользователь отправляет `PATCH /mcps/{id}` с `enabled: false`
- **THEN** подключение выключено, и его токен больше не принимается на `/mcp`

#### Scenario: Несуществующее подключение
- **WHEN** пользователь запрашивает `GET /mcps/999999`, а такого подключения нет
- **THEN** система отвечает `404`

### Requirement: Страница подключений

Фронтенд SHALL иметь страницу `/mcps` с пунктом в меню. Страница показывает таблицу подключений (имя, переключатель `enabled`, `requests_count`, `last_used_at`, действия), позволяет создать, переименовать и удалить подключение, перевыпустить токен. Удаление и перевыпуск SHALL требовать подтверждения, в подтверждении перевыпуска сказано, что подключённые клиенты перестанут работать. Для подключения страница SHALL показывать токен и готовую команду подключения, обе с копированием:

```
claude mcp add --transport http --scope user slogger-<server_name> <endpoint_url> --header "Authorization: Bearer <token>"
```

и вариант для `.mcp.json` проекта, где токен берётся из переменной окружения. `server_name` и `endpoint_url` берутся из `GET /mcps/settings`.

#### Scenario: Команда подключения
- **WHEN** пользователь открывает подключение на инсталляции `stand`
- **THEN** страница показывает команду с именем сервера `slogger-stand`, адресом `endpoint_url` и токеном подключения

#### Scenario: Подтверждение перевыпуска
- **WHEN** пользователь нажимает перевыпуск токена
- **THEN** страница просит подтверждения и перевыпускает токен только после него

### Requirement: Имя инсталляции в шапке

Шапка UI SHALL показывать `server_name` инсталляции из `GET /mcps/settings`, чтобы пользователь видел, с какой инсталляции копирует команду.

#### Scenario: Шапка
- **WHEN** пользователь открывает любую страницу на инсталляции `prod`
- **THEN** в шапке виден `prod`
