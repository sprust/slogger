# Актуализация .env

Прочитать `.ai/README.md` и соблюдать правила проекта. Работать в корне репозитория.
Источник структуры — `.env.example`, целевой файл — `.env`.
Не изменять примеры и `.env.testing`.

## Порядок работы

1. Прочитать оба файла без вывода значений в чат или логи. Не выполнять `source .env`.
2. Определить добавляемые и удаляемые ключи. Показать план без секретов и согласовать
   его по правилам проекта; учесть уже выданное в текущем диалоге согласование.
3. Разбирать присваивания по первому `=`. Сохранять значение целиком, включая пустую строку,
   кавычки, `${...}`, дополнительные `=` и inline-комментарии; не вычислять подстановки.
   При дубликатах ключей или неподдерживаемом синтаксисе (например, многострочных значениях)
   остановиться до записи и сообщить причину. Не угадывать значение и не терять строки.
4. Сформировать результат по строкам `.env.example`: сохранить его комментарии, пустые строки,
   тематические блоки и порядок ключей. Для имеющихся ключей использовать исходные значения
   из `.env`; для отсутствующих — значения из примера. Ключи вне примера удалить.
   Наличие ключа проверять независимо от значения: пустое значение тоже текущее.
5. Если результат совпадает с `.env`, сообщить об отсутствии изменений и не создавать лишний бэкап.
   Иначе до перезаписи создать побайтовую копию `.env.bkp.YYYY_MM_DD_HHMMSS`,
   используя текущее время **UTC** (`date -u +%Y_%m_%d_%H%M%S`). Пример формата:
   `.env.bkp.2025_02_20_084139`; это не фиксированная дата. Не перезаписывать существующий бэкап:
   при совпадении имени дождаться следующей секунды. Закрыть чтение бэкапа для группы и остальных.
   Убедиться через `git check-ignore`, что `.env` и бэкап исключены из Git;
   если нужно, добавить `.env.bkp.*` в `.gitignore`, сохранив существующие правила.
6. Проверить сформированный результат до записи. Записать его через временный файл в том же
   каталоге и атомарную замену, сохранив права исходного `.env`.
7. Проверить после записи: набор и порядок ключей совпадают с примером; значения общих ключей
   совпадают с бэкапом, новых — с примером; дубликатов нет; бэкап равен исходному файлу.
   Проверять без вывода значений и полного diff `.env`.

## Отчёт

Указать путь бэкапа, число добавленных и удалённых ключей и результат проверок.
Не перезапускать сервисы и не сбрасывать кеши без отдельного запроса.
Не добавлять `.env` и бэкап в коммит. Коммит и push — только по отдельному разрешению пользователя.
При изменениях отслеживаемых файлов подготовить сообщение коммита по правилам проекта.
